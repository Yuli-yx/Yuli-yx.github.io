REFERENCE 01

先认职责，再跟数据。

vLLM V1 引擎内含 MRV1 / MRV2；MooncakeConnectorV2 是另一条版本轴。

执行闭环

Scheduler.schedule()
  → SchedulerOutput（本轮计划 + connector metadata）
  → Executor / Worker
  → MRV2.execute_model()（状态、输入、Attention metadata、前向）
  → 常规生成路径：sample_tokens()（采样 + KV 完成回报）
  → Scheduler.update_from_output()

简图省略异步队列、PP、pooling 等分支；零 token 时有 no_forward connector 路径。

术语只记这几项

术语用来做什么
SchedulerOutput把本轮执行计划送给 Worker / runner。
req_statesrunner 侧持久请求状态；不是只存在一轮的 batch。
block table将请求的逻辑 KV 块位置映射到缓存块。
slot mapping本轮 token 写入 KV cache 的槽位映射。
attention metadata本轮 Attention 计算所需的长度、块映射等描述。
KV connector metadata传输协调信息；本身不是 KV 张量。
KVConnectorOutput完成回报、错误及统计等，回流到 Scheduler。

定位入口

要判断什么先看哪处
到底用了哪个 runnerGPU / Ascend Worker 的构造分支
本轮输入如何组织MRV2.prepare_inputs() 与 ModelState
KV 内存如何暴露给 connectorinitialize_kv_cache → get_kv_connector → register_kv_caches；合并阅读 Ascend patch
何时启动加载ActiveKVConnector.pre_forward / post_forward → start_load_kv
哪里收集传输完成常规生成路径 sample_tokens → post_forward → get_finished
零 token 是否仍处理传输MRV2.execute_model → kv_connector.no_forward
收到回报后是否可继续Scheduler 的 KV connector output 处理及请求状态

区分三条线：调度信息、实际 KV 数据、完成回报。数据方向 P → D，不等于提交传输的调用方向。
