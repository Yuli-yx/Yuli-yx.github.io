01 / 分清三段

execute_model 不等于“生成结果已经到 CPU”。

execute_model：更新请求 → 选择执行描述 → prepare_inputs → prepare_attn / ModelState → model 或 graph → ExecuteModelState
sample_tokens：取出状态 → compute_logits / sampling → AsyncOutput → postprocess_sampled
get_output：等待所需输出拷贝完成，整理回传结果

这是常规生成主线；PP、pooling、空 batch、投机解码有额外分支。当前 MRV1 同样把 execute_model() 与 sample_tokens() 分开，因此“分开采样”本身不能作为新旧 runner 的辨别标准。

02 / 模块的边界

RequestState、ModelState 和 nn.Module 不一样。

组件负责什么不应该混成什么
RequestState请求索引、token 历史、computed、last_sampled 等公共状态不等于模型权重
ModelState模型相关的输入、Attention metadata、预处理/后处理生命周期不是每一层 Attention 算子本身
self.model真正的模型 nn.Module；前向给出 hidden states 等前向输出通常不是最终 token id
Sampler从 logits 应用规则并产生采样结果不负责调度下一轮算谁

prepare_attn() 先 gather block tables 并计算 slot mapping；model_state.prepare_attn() 进一步按模型/后端构造 metadata。混合模型可以通过 preprocess_state/postprocess_state 处理额外的状态演化。

04 / 用数字验证

接上上一课：采样完，哪几个长度变了？

假设 C 本轮从 205 生成 206；A 完成 prompt 后生成 105；都采样 1 个 token，无拒绝。C 的 computed 从 5 变 6，total_len 从 6 变 7，last_sampled 变 206。A 的 computed 从 2 变 4，total_len 从 4 变 5，last_sampled 变 105。

C: 已计算 [0..5]，新采样 206 位于 position 6，尚未计算它的 KV。
A: 已计算 [0..3]，新采样 105 位于 position 4，尚未计算它的 KV。
下一轮普通 Decode：两者把 last_sampled_tokens 当作输入。

这就是 computed 和 total_len 分开的理由。本例里 total_len 比 computed 多 1；不能把这个关系推广成所有 chunked-prefill、投机或特殊模型路径的恒等式。

05 / Async-first 的具体含义

先保住缓冲所有权，再讨论重叠。

CPU 可以准备后续步骤，同时设备继续执行已排入 stream 的工作。隐患是 CPU 覆盖一块 pinned host buffer 时，上一轮 H2D 或 UVA 读取可能还没结束。

CPU

更新状态 N → 提交设备工作 → 准备 N+1

GPU

按 stream 顺序：输入准备 N → 前向 N → 采样 N → 状态回写 N

MRV1：synchronize_input_prep() 使用 event 保护可复用 CPU 张量，减少写入与在途传输的竞争。MRV2：把可变 CPU 状态与在途 snapshot 分开；小数组异步拷贝、UVA 轮转 buffer 和 staged writes 等共同支撑这个设计。

StagedWriteTensor 不是“每轮拷整张表”：先在 CPU 记下行、起点和内容，apply_write() 打包差量，设备 kernel 写入基张量。UVA 是设备可访问 host 内存的路径；它不代表所有状态都驻留显存。

AsyncOutput 允许输出拷贝与后续工作重叠；取结果时仍有完成条件。Async-first 是组织原则，不意味着任意功能分支都不存在同步点。

06 / 图执行
