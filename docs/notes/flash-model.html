先把四种状态放到一张图里

GLM-5.3-Flash 在这份 Ascend 实现中对应 glm5next。它不是“每层都保存普通 K/V”的单一 attention 模型：主干按配置选择 MLA attention 或 KDA linear attention；带稀疏索引的 MLA 又有独立的压缩 indexer 和未完成压缩组的环形状态。模型还有 MoE、MTP 等组件，但专家权重与路由不是本专题要传的 cache。

MLA / 稀疏 attention历史 latent KV

按 token 分页，保存用于实际 attention 的历史内容。

KeyPool indexer

压缩 key → 选 Top-K 历史位置

环形 K / gate

保留尚未完成压缩的输入与投机余量

KDA / 线性 attention卷积历史 + 递归矩阵

历史被更新到状态中。恢复某个前缀，需要那个前缀边界的 checkpoint。

Indexer 是选择历史位置的辅助路径，不是第三套独立的主干 attention。此外，模型内部的 KeyPool 是压缩索引机制；外部 KV pool / Ascend Store 是跨请求、跨实例存取 cache 的存储机制。名字接近，职责完全不同。

以下以固定源码解释缓存机制；层数与分布以部署权重配置为准。实际层序列由 layer_types 决定；MTP 层在这里走 MLA 分支，不按主干 KDA 层类型选择。

三条计算路径，四类持久内容

路径做什么需要留到下一步的内容共享难点
MLA用低维 latent 表示历史 KV，再执行 attention；稀疏版本按索引选择历史位置主 latent cache；RoPE 部分取决于模型配置，本次观测到 NoPE 主 cache 的 rope view 为空不能套用普通每 head 各一份 K/V 的地址假设
KeyPool indexer将若干 token 的 key/gate 聚合成压缩 key，参与历史 Top-K 选择已完成的压缩 key；可选量化布局还可能有 scale逻辑 token 数不等于压缩 cache 行数；没完成的一组不能当有效行写池
KDA卷积处理局部历史，再更新递归状态；prefill 与 decode 可走不同算子路径conv state 与 recurrent state原地更新；前缀命中必须恢复同一边界状态，不能只找历史 KV
Indexer 环形 tail保存未完成压缩组及投机 lookahead 的 raw key/gate请求独占的 FP32 环形页不是完整前缀块；同一页会反复覆盖，PD 任意交接边界需要精确快照

可以这样理解 KDA：attention 的历史信息压进了一个不断更新的状态，而不是保留所有 token 的完整 K/V。为了支持前缀恢复，运行时仍可能保存多个可复用 checkpoint；“状态大小固定”不意味着整个服务只分配一个 state。

Ascend 怎么管理这些 cache

模型声明 spec主 attention、indexer、tail 和 KDA 各自声明缓存需求
→
Engine 规划 group确定块粒度、page 成本、分组与 block 数
→
Worker 建立 view原始 backing → shape / stride / component offset
→
Scheduler 分配使用权请求 block table 与 checkpoint 引用

Indexer 与 tail 通过 AttentionLayerBase 注册到静态上下文，但它们设置了 align_kv_cache_with_mamba=False，有模型专用的小页布局。KDA 则用 Mamba/SSM 的状态管理和对齐 checkpoint 契约。同组共享的是 block 管理规则，不代表不同层共享同一份内容。

必须分清三种粒度：scheduler 的逻辑 block、算子读取的 kernel page、prefix hash 的粒度。本次模型实验实际逻辑块为 640 tokens；MLA kernel page 为 128 tokens，因此一逻辑块覆盖 5 个 kernel pages。CLI 输入 128 不能直接当作最终逻辑块大小。

def view_kpool_tail_cache(
    layer_name: str,
    kv_cache_spec: AscendIndexerKPoolTailSpec,
    raw_cache: torch.Tensor | tuple[torch.Tensor, ...],
    num_blocks: int,
) -> list[torch.Tensor]:
    if not isinstance(raw_cache, torch.Tensor):
        raise ValueError(f"KPool tail cache for {layer_name} must use one raw tensor.")
    typed_slot = raw_cache.view(kv_cache_spec.dtype)
    dtype_size = get_dtype_size(kv_cache_spec.dtype)
    page_el = typed_slot.numel() // num_blocks if num_blocks else 0
    tail_block_el = kv_cache_spec.unpadded_page_size_bytes // dtype_size
    if num_blocks and tail_block_el > page_el:
        raise ValueError(
            f"KPool tail cache for {layer_name} does not fit one small page: "
            f"tail={tail_block_el} elements, page={page_el} elements."
        )
    return [
        torch.as_strided(
            typed_slot,
            size=(num_blocks, kv_cache_spec.block_size, 2 * kv_cache_spec.head_size),
            stride=(page_el, 2 * kv_cache_spec.head_size, 1),
        )
    ]

压缩尾部与投机状态：为什么不能漏

压缩比为 4 时，只有位置满足 (position + 1) % 4 == 0 才产生一个完成的压缩组。比如已计算 799 tokens，已完成 199 组，还剩 3 tokens 的尾部历史。恢复时只搬 199 行压缩 key 不够，下一 token 完成新组时还需要这些历史 raw key/gate。

def format_indexer_kpool_slot_mapping(
    slot_mapping: torch.Tensor,
    positions: torch.Tensor,
    logical_block_size: int,
    compress_ratio: int,
) -> torch.Tensor:
    """Map completed token pools onto the compressed indexer cache."""
    if compress_ratio <= 1 or logical_block_size <= 0 or logical_block_size % compress_ratio:
        raise ValueError(
            f"logical_block_size={logical_block_size} must be divisible by compress_ratio={compress_ratio}."
        )
    valid = (slot_mapping >= 0) & (torch.remainder(positions + 1, compress_ratio) == 0)
    safe_slots = slot_mapping.clamp_min(0)
    block_ids = torch.div(safe_slots, logical_block_size, rounding_mode="floor")
    offsets = torch.remainder(safe_slots, logical_block_size)
    compressed_slots = block_ids * (logical_block_size // compress_ratio) + torch.div(
        offsets,
        compress_ratio,
        rounding_mode="floor",
    )
    return torch.where(valid, compressed_slots, torch.full_like(compressed_slots, -1))

def get_kpool_tail_ring_capacity(vllm_config: VllmConfig, compress_ratio: int) -> int:
    """Keep the open pool plus every not-yet-accepted speculative token.

    Target verification writes all draft rows before rejection sampling is
    known.  The first row is the already-sampled token and is committed; the
    remaining ``num_speculative_tokens`` rows are lookahead.  Retaining that
    lookahead in addition to one full pool prevents rejected rows from wrapping
    around and destroying committed history that a replayed boundary token
    still needs.
    """
    speculative_config = getattr(vllm_config, "speculative_config", None)
    lookahead = int(getattr(speculative_config, "num_speculative_tokens", 0) or 0)
    if lookahead < 0:
        raise ValueError(f"num_speculative_tokens must be nonnegative, got {lookahead}.")
    return compress_ratio + lookahead

恢复方式需要的内容边界
