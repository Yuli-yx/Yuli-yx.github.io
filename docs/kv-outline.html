KV Cache 管理：章节与模型案例

16 章，按共同机制、真实模型和横向对照组织。

先学习共同对象和管理机制，再分别拆解真实模型，最后按同一请求和统计口径对照。已编写的 3 章可以直接阅读；其余 13 章列出了范围，正文尚待编写。

模型案例包括普通 GQA、Qwen3.5/3.6、Kimi K3、DeepSeek V4、GLM-5.3 和 GLM-5.3-Flash。每个案例都将固定 checkpoint 与源码版本，分别记录缓存内容、spec、tensor 布局及请求生命周期。

5. 每个模型案例怎样展开？

  1. 列明 checkpoint、配置、两仓提交、dtype 与并行前提。
  2. 画出与缓存有关的层和组件，说明各自保存什么。
  3. 逐项记录 shape、dtype、产生者、消费者和更新时点。
  4. 从模块 spec 追到 backend 定制、cache group 和物理 view。
  5. 按元素、字节、block 与层数计算容量，区分三种统计口径。
  6. 跟踪 prefill、decode、恢复和结束时的状态变化。
  7. 说明该模型的边界条件，再与前一案例比较。

KV Cache 专题负责说明模型保存什么、怎样管理；PCP/DCP、P/D 和 KV Pool 专题再解释这些对象如何分布、传输和共享。
