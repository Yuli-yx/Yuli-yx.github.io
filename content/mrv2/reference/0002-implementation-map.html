三条最重要的关系

batch_idx → idx_mapping → req_state_idx
position = computed + 本轮请求内偏移
常规无拒绝：computed += query_len；total_len += num_sampled

per-step InputBatch 可引用长期 InputBuffers 的切片。req_state_idx 不是 KV block id；GPU 状态也不一定与 CPU mirror 在每个时刻精确相等。

新旧 runner 的差异

MRV1：CachedRequestState + 持久输入 batch，填洞和顺序调整维护相关状态。MRV2：RequestState 与本轮输入分离，用 idx_mapping gather，设备侧准备部分输入并回写状态，StagedWriteTensor 提交差量，ModelState/GraphManager/Sampler 等边界更明确。

两者都已有异步与采样拆分；不能把 MRV2 概括成“V1 引擎换代”或“所有数据都放 GPU”。Ascend 使用 override + patch，需要追实际绑定。

数据例子

C: state=1, computed=5, q=1, last_sampled=205, blocks=[10,11]
A: state=3, computed=2, q=2, tokens=[101,102,103,104], blocks=[20]
req_ids=[C,A] → idx_mapping=[1,3]
query_start_loc=[0,1,3]
positions=[5,2,3]；seq_lens=[6,4]
input_ids=[205,103,104]；logits_indices=[0,2]
普通 Attention、block_size=4：slot_mapping=[45,82,83]

无投机、无并行、无图 padding 的普通 Attention 教学例子。采样后 computed 和 total_len 分别变化，不能把新采样 token 当成已经生成 KV。
